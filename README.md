# millsage · 重逢的间隙

以 BanG Dream! millsage 的泽海奏多与汐见萤为主题的非官方互动网站。仓库包含完整网页源码、Live2D 模型、车库场景、贴图、动作与浏览器运行时，运行时无需访问外部素材服务。

在线访问：[millsage · 重逢的间隙](https://StevenYang723.github.io/millsagepage/)

## 互动

- 主页将奏多与萤的半张脸拼合，呼吸与眨眼同步。
- 点击左侧奏多，右侧萤化作白色羽毛向上飘散，然后进入奏多版本的原版车库场景。
- 点击右侧萤，左侧奏多化作玻璃碎片向下消失，然后进入萤版本的原版车库场景。
- 点击车库钢琴前的目标角色、右下角返回按钮，或按 `Escape`，通过时空扭曲动画返回主页。
- 右上角提供暂停动态、全屏与素材说明。

车库播放游戏原始 Spine `home_start` 动作，每轮结束后停留再重播。主页使用原始 Live2D 模型；同步呼吸、眨眼和页面转场由网页控制。

## 本地运行

安装 Node.js 18 或更新版本，在仓库根目录执行：

```sh
node serve.mjs
```

打开 <http://127.0.0.1:8765>。需要支持 WebGL 的现代浏览器。请通过 HTTP 服务访问，直接双击 HTML 文件无法正常加载模块和模型。

无需安装 npm 依赖，也无需构建。首次加载约 33 MB，进入车库后再加载对应场景。

## 手机性能

手机、窄窗口和低内存设备会自动使用轻量绘制配置：主页 30 帧同步呼吸、DPR 上限 1.25，以及较少的羽毛、玻璃碎片和扭曲叠层。车库的原版骨骼、动作关键帧、时间轴和角色贴图不变；仅将背景在浏览器中缩小至 2048×2048，减少纹理内存。

主页加载完成后会在空闲时提前下载车库素材（省流量模式和 2G 连接下跳过）；转场只并行下载，场景解码和创建等到转场结束。两侧共用相同的背景下载缓存，手机只保留最近一个车库渲染实例，切换另一侧时释放旧场景。

原始素材仍完整保留。手机单个场景两张贴图的 RGBA 基础像素量从约 80 MiB 降到 32 MiB，实际内存还包括角色骨架、GPU 缓冲等。首次下载量仍约 8 MB，缓存和预载不改变网络本身的速度。

## 验证

```sh
node --test tests/*.test.mjs
```

测试校验 242 个原版资源的 SHA-256、素材与模块路径、转场调度、缓存释放、失败重试和移动端绘制预算。GitHub Pages 发布前也会执行这些检查。界面按手机尺寸进行了浏览器验证；这不代替具体手机上的帧率实测。

## 文件结构

```text
dist/
  index.html       页面结构
  style.css        布局、视觉样式与动画
  app.js           主页模型、交互状态与转场
  garage.js        车库场景播放与交互
  credits.txt      素材来源与许可证索引
  assets/
    kanata/        奏多 Live2D 模型、贴图与动作
    hotaru/        萤 Live2D 模型、贴图与动作
    immersive/     两套原版车库场景、共享贴图与渲染器
serve.mjs          本地静态服务器
README.txt         离线使用说明
```

## 静态部署

GitHub Pages 使用 [部署工作流](.github/workflows/pages.yml) 发布 `dist/`。更新 `main` 分支中的网站文件后会自动部署，也可以在仓库的 Actions 页面手动运行 `Deploy GitHub Pages`。

将整个 `dist/` 目录作为网站根目录发布到支持静态文件的托管服务。保留所有文件名、子目录与二进制资源，不需要服务器端代码。
